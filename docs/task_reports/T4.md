VERIFIED APIS:
- mink 1.4.0, inspected from the installed package (not the docs site). qpsolvers 4.13.0 available_solvers is ['daqp'] only.
- mink.FrameTask(frame_name, frame_type, position_cost, orientation_cost, gain=1, lm_damping=0). set_target takes an SE3. compute_error returns a body twist. frame_type "site" is supported.
- mink.SE3.from_matrix(4x4) and SE3.from_rotation_and_translation(SO3, translation). Internal vector is wxyz_xyz. SO3.wxyz is (w, x, y, z). Pose.to_matrix matches that convention, confirmed by IK on xarm7, panda, and so_arm100.
- mink.Configuration(model, q=None) allocates its own MjData. update(q) runs kinematics. integrate(velocity, dt) and integrate_inplace(velocity, dt) use mj_integratePos. get_transform_frame_to_world(name, type) returns SE3. q is a copy of qpos.
- mink.ConfigurationLimit(model, gain=0.95). The inequality is on delta q; dt is unused. gain in (0, 1].
- mink.CollisionAvoidanceLimit(model, geom_pairs, gain=0.85, minimum_distance_from_collisions=0.005, collision_detection_distance=0.05). geom_pairs is a sequence of (geom-name group, geom-name group). Unnamed geoms cannot be listed. Wired behind solve_ik(..., avoid_collisions=True). Default is off so the 95% FK test is kinematic.
- mink.DofFreezingTask(model, dof_indices) passed as a solve_ik constraint freezes every dof that is not an arm joint, including the diff-drive free joint.
- mink.solve_ik(configuration, tasks, dt, solver, damping=1e-12, safety_break=False, limits=None, constraints=None) returns a tangent velocity v = delta_q / dt. NoSolutionFound if the QP fails. limits=None installs ConfigurationLimit. This code passes limits explicitly and solver="daqp".
- A random joint vector's site pose, solved from the home configuration with max_iters=40, succeeded on 30/30 samples for ufactory_xarm7, franka_emika_panda, and trs_so_arm100 in the test run (the test threshold is 95%).
- A 6 cm Cartesian segment on xarm7 stayed within 0.08 mm of the straight line in the probe and within 2 mm in the test.
- RRT-Connect around a 6 x 5 x 8 cm wall at (0.35, 0.19, 1.27) m returned a collision-free path in about 0.13 s. The straight joint line collides. The RRT block in planner.py is 126 lines.

INTERFACE CHANGES:
CHANGE REQUEST: RobotPlacement.arm_id: str | None = None. When set, the placement's robot_id is the base and arm_id is mounted on its mount site with the same empty-prefix attach compose_mobile_manipulator already uses. Omitted arm_id keeps every existing scene unchanged. placed_spec(catalog, placement) returns the composed RobotSpec and is cached. create_robot and the initial joint state use that spec, so the mounted arm's joints are prefixed with the instance name.

No T1–T3 function signature was removed. SimArm.move_pose no longer raises NotImplementedError; it returns a MotionResult. tests/sim/test_sim.py now checks that a 2 cm pose move succeeds.

KNOWN LIMITATIONS:
- uv sync --all-extras still fails: pyaudio needs portaudio.h.
- CollisionAvoidanceLimit is optional and off by default. Many Menagerie finger geoms have no name, so they cannot be put in a geom pair.
- RRT-Connect does not treat robot self-collision as blocking. It does reject new contacts with scene bodies.
- move_pose succeeds when the end effector is within 5 mm and 0.05 rad after the trajectory, or when the joints meet the 2e-3 rad / 1e-2 rad/s settle used by move_joints. SO-ARM position servos (kp 50) often stop a few milliradians short of 2e-3.
- The diff-drive free joint is held kinematically after every physics step so the chassis does not fall while the arm moves. A weld from that arm to a free cube is unstable; the mobile example does not weld. It drives 1.5 m, reaches the cube pose, and closes the gripper. The SO-ARM home jaw is not a parallel pinch, so this pick does not lift the cube off a pedestal.
- safe_transit commands the transit 2 mm above clearance_z_m so tracking error stays at or above the requested clearance.
- Attaching Menagerie models still warns about option conflicts. The parent values are kept.
